# TA-X7 bounded reporting contracts plan

Status: focused plan for coordinator review. No implementation or environment change is authorized by this file.

## Authority and boundaries

TA-X7 implements the reporting contracts in `EXPANSION_FRAMEWORK.md` and the worked cases in `EXPANSION_ACCEPTANCE_CASES.md`. It consumes the immutable X1-X6 evidence already present. It does not rewrite source facts, enable a feed, infer a missing commercial rule, create cached truth, expose contact data, activate a monitor, add UI, or write production.

Every API requires explicit organization plus active membership and a purpose-specific capability. Every query has a finite as-of/window, a hard limit, stable server-resolved cursor, explicit grain, metric identifier/version, currency or source scope where relevant, coverage/completeness fields, and drill-down identifiers. Row-level filters are applied to the full authorized eligible set before aggregation; aggregate filters are applied only after aggregation. No client-side page is used as the analytical dataset. Unknown stays NULL/unavailable, never zero.

## Dependency-ordered delivery

### X7a: attendance interval normalization and weekly metrics

Consume only reportable X6h companion segments. Authorized-platform events remain quarantined until a separate provider normalization contract is approved. Build a service-only projection that applies the current reviewed stream attribution and effective-customer mapping without rewriting the raw stream. For one organization, customer, session and source, union overlapping `[start,end)` ranges with PostgreSQL multirange aggregation before summing duration. Different tabs, devices, reconnects and gap segments remain visible in drill-down but never double-count overlap.

Add immutable reviewed coverage assertions, separate from raw presence. A finite query window is never proof of collection coverage. An assertion identifies organization, source, bounded interval, policy/version basis and `complete`, `partial` or `unavailable`; it never manufactures attendance. Assertions are append-only and auditable, with explicit supersession/revocation, compare-and-swap revision, idempotency key and deterministic conflict resolution for overlapping intervals. A `complete` assertion cannot override known collection-disabled, incomplete or unavailable evidence without an explicit reviewed supersession that preserves the displaced assertion. Without reviewed coverage, a gap is `unknown`, not observed zero. Add bounded RPCs for source-grained attendance detail and weekly attendance. Callers provide a finite observation window, IANA reporting timezone and explicit week-start day; no business default is invented. Local week boundaries are converted to instants in that timezone, including DST transitions. Generate every local calendar week intersecting the selected window. A session contributes once to the week containing its first eligible reportable attendance instant across the complete session, not the first event clipped into the requested window, so changing the query window cannot move the session between weeks. Its duration is clipped across every affected weekly duration bucket. Reconnects never add a distinct session.

Return week start/end, partial-week flag, asserted/unknown coverage seconds and classification, distinct sessions, unioned observed seconds, source label, metric ID/version and contributing segment/session IDs through a separate bounded drill-down. `observed_distinct_sessions_per_calendar_week` always discloses its lower-bound nature. `complete_window_average_sessions_per_week` is NULL unless reviewed complete coverage spans every instant of the selected denominator; when complete, its denominator is the number of intersecting local calendar weeks, including supported zero-attendance weeks. A partially clipped first/last week remains explicitly partial even when its selected subrange is fully covered. Ended-session anomalies and unmatched/unattributed streams are excluded from customer metrics but counted in disclosed exclusions.

Reporting is **restated current interpretation at a requested observation cutoff**, not knowledge as historically understood at that time. Event occurrence is clipped by the cutoff, while later-recorded eligible corrections, current reviewed attribution and current session bounds may restate prior periods. An org reporting-revision relation is advanced by inserts/changes to presence, coverage, attribution, session bounds, effective-customer merge/split identity, and every policy or retention input actually consumed by the projection. Revision capture and projection reads occur in one transaction snapshot: a concurrent input change cannot return new data with the old revision or old data with the new revision. Every response returns metric version, observation cutoff and dataset revision. Follow-on pages must present the same revision; a later correction/status/attribution/identity/policy change rejects the stale cursor and requires restart. No page silently mixes watermarks.

Acceptance fixtures: two tabs overlap for ten minutes and union to ten, not twenty; missing disconnect stops at expiry; four distinct sessions all in week one over an explicit two-week completely asserted window average to two sessions/week; the same empty week without coverage is unknown rather than zero; reconnects do not increase distinct sessions; changing the query window does not move a cross-week session's count bucket; DST fixtures use the requested timezone; overlapping coverage assertions resolve deterministically and revoked/superseded assertions retain their audit trail; a complete assertion cannot erase known collection-disabled evidence; later attribution/session/customer-identity/policy correction invalidates the old cursor/revision; a concurrent input change cannot pair mismatched data and revision; hostile org, missing capability, NULL/unbounded inputs and quarantined provider rows fail closed.

### X7b: official customer spend and denominators

Build a service-only line-contribution projection over approved posted transaction lines, current selective transaction attribution and whole-record effective-customer mapping. Use line-level purchase kind, channel, location, product/configuration/unique item, session and capture source. Official merchandise contribution is the known posted/finalized merchandise amount plus only effective additive adjustments under the X6d cancellation/reinstatement contract. Shipping and tax are separate measures. Provisional X6a/native-board activity is returned by a separate, explicitly labeled API and never enters official totals.

Require one explicit currency, finite occurrence/as-of period and metric ID. Do not convert currencies. Return gross merchandise, discounts, net merchandise before adjustments, effective refund/cancellation/correction delta, official net merchandise, shipping and tax separately, order count, purchasing-break count and coverage/unknown-component counts. `spend_per_attended_break` divides only compatible official **break** net merchandise for the selected cohort by X7a distinct attended break sessions in that same cohort. Retail/unclassified spend is never smuggled into that numerator. `spend_per_purchasing_break` divides compatible official break net merchandise by distinct posted purchasing sessions. Transactions with missing/foreign/unmatched session identity, unknown monetary components or attendance outside proven coverage are disclosed as coverage/exclusion counts, not coerced to zero. Zero denominators return NULL, not zero or infinity. Retail, break, unclassified and combined are separate rows/grains. A multi-product break line without an explicit conserving allocation remains `mixed_unallocated`; it is not repeated under each product.

Acceptance fixtures: $200 merchandise less $50 refund equals $150 while $20 shipping and $10 tax remain separate; $100 posted retail plus two $30 provisional break sales remains official $100/provisional $60 until posting, then official combined $160; four attended breaks and two posted $30 break purchases yield $15 per attended break and $30 per purchasing break; native plus reconciled import contributes once; refund/resale stays on separate sale/customer identities; explicit unattribute removes contribution without rewriting the transaction.

### X7d: eligible observation history and composable screener

Use only `e10_current_market_observations` plus governed catalog/product relationships and tenant-owned copy records. Add a typed bounded query whose scope is explicitly `catalog`, `owned`, or `completed_sale_observation`. Filters cover sport, league, canonical subject, maker, line/set, release and season range, evidence-backed rookie designation versus explicit rookie-season dimension, exact parallel, governed color/finish family, language/edition, raw versus graded, grading company/grade, print-run denominator versus observed copy serial numerator, evidence-backed jersey match, source, currency, observation window and optional caller-supplied numeric thresholds. Unknown governed mappings are excluded from exact filters and returned in an exclusion count. Catalog cohorts, owned copies and completed-sale observations retain distinct grain.

Transaction-level filters are applied before grouping. Sale count/mean/median/latest constraints are aggregate filters applied after the complete eligible cohort is selected. Asking price, completed sale, acquisition cost and estimated value never share a measure. Cursor ordering includes the full explicit sort tuple and stable cohort key. Drill-down returns the exact contributing observation IDs and source lineage. Corrected imports use only current eligible interpretations while preserving supersession lineage in drill-down. The query works with local/manual/imported records when every connector is absent.

Acceptance fixtures include the $500/$1500 mean-order case, optional per-sale filter, ask-versus-sale separation, no-sale catalog match with unavailable price, multi-subject lookup, release/rookie distinction, copy-versus-observation grain, corrected import eligibility, and two-org private-observation isolation.

### X7e: inventory lifecycle, exposure, grading and valuation seams

Reconstruct eligible listing intervals from versioned commercial events only where subject/listing/copy identity and occurrence time are sufficient. A listing disappearance is not an end or sale. For one physical copy, union overlapping channel intervals before calculating active exposure. Keep receipt-to-sale/as-of inventory age, receipt-to-first-published intake delay, first-list-to-sale and active exposure as distinct metrics. Unknown timestamps produce unavailable measures and explicit exclusions.

Add governed append-only structures for grading assessments/regrades, dated population snapshots and versioned estimate/index evidence with source, method, observed/recorded time, currency where applicable, scope, supersession and review status. A regrade attaches another assessment to the same physical copy, never another owned item. Population is not print run; an index estimate is not a sale. No source row is invented when unavailable.

Add bounded valuation coverage over tenant holdings and typed eligible evidence. Acquisition/actual cost, asking price, completed sale and estimated/index value remain separate. A caller selects method, currency, as-of cutoff and freshness bound. Return valued/unvalued counts, evidence age/source/method/version, population snapshot date and unknown cost separately. No evidence means unknown, not zero. Acquisition contribution is reported separately from market movement.

Acceptance fixtures cover Jan 1 receipt/Jan 3 list/Jan 4 pause/Jan 6 resume/Jan 9 sale, overlapping channel union, unsold censoring, sparse/no evidence, stale estimate, feed independence and acquisition-versus-appreciation separation.

## Security, pagination and correction rules

- New projections remain service-only. Public reporting RPCs are `SECURITY DEFINER`, anon-closed, self-authorize explicit org membership/capability, and expose only purpose-limited fields.
- Financial/customer metrics use a financial-report capability separate from contact/notes. Screener/catalog reads cannot expose another tenant's observations, costs, sales or holdings.
- Every keyset cursor is bound to organization, query fingerprint, metric version and as-of cutoff. Server-side cursor resolution preserves PostgreSQL timestamp precision and rejects foreign/stale cursors.
- No materialized aggregate is authoritative in X7. If later performance requires one, it must carry query/metric version, as-of cutoff and correction watermark and be rebuildable from immutable evidence.
- Corrections, refunds, identity changes and listing supersessions change projections by selecting current eligible interpretation, never by rewriting original evidence.
