# TA-X6h observed attendance evidence plan

Status: approved local implementation draft under precommit review. No staging, UI telemetry, external feed, job, or production change has occurred.

## Scope and authority

This slice implements only the attendance-evidence contract in `docs/EXPANSION_FRAMEWORK.md`: permission-scoped session/customer presence; distinct join, heartbeat and leave evidence; bounded missing disconnects; reconnect and multiple-device identity; session-duration limits; explicit source and coverage; and separation from commercial activity. It supports the attendance acceptance cases without calculating weekly averages or spend denominators. TA-X7 retains all aggregation, timezone, week-boundary, zero-week, partial-coverage, metric-definition and reporting responsibilities.

The existing `e10_session_viewers` relation is admission/participation state, not attendance evidence. Its existence does not prove presence or duration. `e10_break_sessions.created_at`, `ended_at`, status and organization are the native session authority. A companion connection is evidence that an authorized client remained connected to the seller-branded companion surface. It is labeled **observed companion time**, never video watch time. An optional licensed platform source remains separately labeled **authorized platform attendance** and is never inferred from companion or purchase activity.

No hold, bid, assignment, native sale, customer transaction, payment, settlement, inventory movement, commercial event or financial adjustment is created by attendance telemetry. Viewer authority is not widened to any commercial writer or table.

## Evidence model

Add client-closed, organization-owned `e10_presence_collection_policies`, `e10_session_presence_streams`, `e10_session_presence_segments` and `e10_session_presence_events`, plus an idempotency receipt relation and immutable reviewed attribution decisions. Collection policies are server-owned and disabled/unconfigured by default. X6h seeds no organization duration, notice, expiry, provider or collection enablement.

A stream is a stable source observation identity, not an aggregate. It contains organization and session IDs; source class (`companion` or `authorized_platform`); a bounded source/provider key; a source-scoped connection identifier; the observed auth user when applicable; a nullable customer snapshot resolved only from current verified identity evidence; resolution status; a pseudonymous client-instance identifier where supplied; server-resolved policy/version and source-coverage label; actor; and creation time. Companion source identity is unique by organization, session, observed auth user and connection ID, so a guessed/copied connection ID cannot append to another person's stream. Idempotency receipts carry the same user/source scope. A genuinely new connection ID creates a new stream. Different tabs/devices remain distinct streams so overlap can later be unioned rather than counted twice.

Each segment has a monotonic sequence within a stream and snapshots the server policy version, heartbeat expiry, retention expiry and applicable coverage. Each immutable event belongs to one segment and records a monotonic event sequence, event kind (`join`, `heartbeat`, `leave`), server receive time, optional client-reported occurrence time, external source event identity where applicable, request fingerprint, actor and raw evidence. Server receive time is authoritative for companion coverage. Client-reported time is retained as an untrusted claim and never extends companion duration. A heartbeat received after the prior segment's server expiry starts a new segment at that heartbeat, preserving the gap; it never retroactively bridges join to the late heartbeat. An explicit reconnect may also create a new connection/stream. Authorized-platform occurrence time is accepted only through the service-only platform writer with explicit provider/source/coverage provenance; it is not promoted to companion evidence.

The current-stream projection may expose the latest sequence and state, but raw streams, segments and events are never rewritten by customer merge/split, identity detach, session correction or later source evidence. Immutable reviewed presence-attribution decisions may associate or unassociate a stream with an active terminal organization customer under CAS and `act.manage_customers`; the raw observed user and original customer snapshot remain unchanged. Customer reporting later applies the current reviewed decision and effective-customer mapping while retaining original user/customer/source facts. Unmatched authenticated viewers remain `customer_id=NULL`; later verification does not automatically back-attribute earlier anonymous or unmatched evidence.

Attendance evidence is sensitive relationship telemetry. Direct table access is revoked from `PUBLIC`, `anon` and `authenticated`, all relations have RLS enabled with no client policies, and bounded reads are capability-checked. Evidence rows are update-immutable. Collection-policy versions are immutable except for a service-owned enabled switch, so a stored version cannot change meaning. Deletion is not exposed to clients; a later explicitly reviewed retention executor may delete expired evidence under the stored policy key and must produce an audit record. X6h does not invent a retention duration or enable a purge job. The collection-notice and retention-policy keys are required provenance, not a claim that consent or retention policy has already been legally approved.

## Companion self-observation writer

Add `e10_record_own_companion_presence`, a `SECURITY DEFINER` RPC callable by `authenticated` and closed to anon. It takes a globally unique session ID, bounded connection and client-instance IDs, one event kind, optional client-reported time/evidence, an acknowledgement of the current server notice version and an idempotency key. It does not accept another user ID, customer ID, organization ID, source class, platform-watch flag, server receive time, retention policy, heartbeat expiry or retention expiry.

The writer derives organization from the session and uses `auth.uid()` as the only subject. It resolves one enabled server-owned organization collection policy and rejects unconfigured/disabled collection, stale notice acknowledgement or expired policy. The client cannot invent or extend policy, heartbeat or retention values. It permits a call only when the caller has current session access as an explicit session viewer, owned-slot participant, session owner/member, or codeless published spectator under the existing session predicate. Private-session code redemption must already have created the caller's own `e10_session_viewers` row. A caller cannot name another session organization, another user or a hidden/private session. The writer never calls `current_org()` for a membership-less viewer.

Authorization and collection policy are checked before and after locks. The writer acquires the organization customer-topology lock before resolving a verified customer, then deterministic receipt, stream and session locks. It captures authoritative server time after synchronization and locks and rechecks the session. New join/heartbeat evidence requires an active session. A leave may close an existing stream after session end, but effective duration remains bounded. The first event must be join; heartbeat cannot follow explicit leave; a second join on the same connection is a retry or invalid transition; reconnect uses a new connection ID. A late heartbeat after expiry begins a new segment rather than filling the lapse. Policy-defined spacing and actor/session-wide event limits also cover new connection IDs, so connection fanout cannot bypass the resource bound. A stream must reconnect when the current policy version or notice changes; events never inherit new policy meaning inside an old stream or segment. Exact user-scoped idempotent replay returns the original result, changed reuse fails, and the same key or connection ID used by another user cannot collide with or reveal the first user's stream.

For each companion segment, effective coverage begins at its first server-received join/heartbeat and ends at the earliest of explicit server-received leave, last server-received join/heartbeat plus the versioned server expiry, finite session `ended_at`, policy retention expiry or the observation cutoff. A delayed leave is never treated as fresh presence. Client clocks cannot move either boundary. If session status is ended while `ended_at` is NULL/nonfinite, or a purported end precedes the segment start, the projection emits a zero-duration fail-closed interval with an anomaly flag; bounded reads exclude it rather than inventing post-end coverage. Clipping to a requested window retains original onset/end and returns clipped bounds separately, so cursor identity and ordering remain stable. A missing leave therefore expires; it never implies infinite presence. No background heartbeat-expiry job is required because the segment projection applies the bound deterministically.

## Authorized-platform evidence seam

Add a separate born-locked service-role-only writer for optional authorized-platform presence. It requires explicit organization/session, provider, durable provider attendee and event IDs, source occurrence time, coverage label, evidence and idempotency key. It validates the organization/session pair and an enabled server-owned provider policy, and never accepts a provider assertion as a platform-global login or customer identity. Customer attribution is nullable and uses only an existing reviewed/verified organization relationship. Provider events may arrive out of order: immutable provider sequence/time evidence is retained and append-only correction/supersession records identify a replaced interpretation. No mutable first-party/server clock is substituted for provider occurrence time. Provider evidence cannot create `e10_session_viewers`, authorize companion access, or assert payment/commercial activity.

No connector, polling, webhook, external API, scheduled monitor or live feed is implemented. Authorized-platform events are retained as immutable, source-timed, provider-scoped evidence with exact replay and append-only corrections, but are deliberately quarantined from interval projection. Provider-time normalization is a required TA-X7 remainder, not an X6h completion claim. The seam is dormant until source rights, actual payloads and retention terms are separately reviewed.

## Bounded reads and interval projection

Add a server-side segment projection and a bounded organization RPC guarded by active membership plus a new ungranted-by-default `act.view_customer_engagement` capability. The read accepts explicit organization, session/customer filters, a required finite time window, bounded limit and keyset cursor at stable segment grain. The server resolves the cursor UUID back to its exact microsecond timestamp, avoiding client timestamp-rounding duplicates. It returns source class, coverage, immutable policy/notice provenance, original and effective customer IDs, current attribution action/revision/decision, stream and segment identity, original onset/end, clipped start/end, expiry reason and evidence-completeness flags. It excludes contact details and never returns raw evidence by default.

The interval projection is source-grained. It does not sum overlapping streams, label companion time as watch time, calculate distinct sessions/week, fill zero weeks, combine companion/platform sources, or join spend. TA-X7 owns union-of-overlapping-interval logic per customer/session/source, distinct-session and weekly denominators, reporting timezone, complete versus partial observation windows, source drill-down and separation from posted/provisional spend.

## Deterministic verification

The focused local/staging gates must prove:

- an authorized viewer can record only their own companion join/heartbeat/leave for an accessible real session;
- another user ID, foreign organization/session, private unredeemed session, anonymous caller, and malformed/unbounded identifiers fail closed;
- viewer attendance calls create zero commercial events, activities, transactions, lines, adjustments, inventory movements or native sales;
- exact retry is stable, changed reuse fails, cross-user key/connection reuse reveals nothing, and two concurrent first events produce one stream/event sequence;
- heartbeat/leave transition races serialize without duplicate sequence or post-leave heartbeat;
- session-end versus heartbeat uses an exact-backend lock-wait proof and cannot extend past `ended_at`;
- identity detach and whole-record merge versus join use topology-first exact-backend waits; raw presence is unchanged and post-wait attribution uses current evidence;
- a revoked/ambiguous/conflicting/unmatched identity remains unattributed;
- two overlapping companion streams for one customer preserve two raw streams while the interval fixture's union is ten minutes, not twenty;
- join, long lapse, heartbeat and leave produce separated segments with a visible gap; a missing disconnect ends at heartbeat expiry; client-reported future/past timestamps cannot extend the authoritative interval;
- reconnect uses a new stream but does not create another distinct attended session;
- authorized-platform and companion evidence stay separately labeled and cannot impersonate each other;
- disabled/unconfigured collection and stale notice acknowledgement fail closed; server policy alone supplies expiry/rate/retention values;
- an ended session with NULL/nonfinite or pre-segment `ended_at` yields no reportable duration and is labeled incomplete/anomalous;
- out-of-order platform evidence and reviewed corrections remain append-only and source-timed while an unavailable/unverified provider stays dormant;
- reviewed presence attribution can correct or remove an association without rewriting raw presence or auto-attributing pre-verification evidence;
- the bounded read rejects NULL/unbounded windows and limits, preserves stable segment cursor and full UUID/source provenance, and denies missing capability and hostile tenants;
- all new relations are RLS-enabled and client-closed, public RPCs are anon-closed, internal/platform writers are client-closed, default grants remain zero, advisors add no unexplained ERROR, and cleanup residue is zero;
- clean database replay, X6a-X6g regressions, A7, default privileges, exact-head CI, explicit staging target/ledger evidence and production read-only proof all pass.

## Explicit remainder

This slice does not add UI telemetry, JavaScript heartbeats, video-player measurement, platform integrations, scheduled expiry/purge jobs, notifications, exports, charts, AI answers or production changes. It does not claim attendance history is complete. TA-X7 must define and test aggregation grain, overlap union, source combination, reporting timezone, zero-attendance weeks, partial coverage, distinct attended sessions, spend denominators and drill-down. Consequential collection/retention policy values and any licensed platform source remain subject to separate owner/legal review before external use. TA-X7 is also required to define provider-time normalization and promotion criteria before quarantined authorized-platform events may participate in any interval or attendance metric.
